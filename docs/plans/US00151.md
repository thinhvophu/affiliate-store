# Implementation Plan — US00151: Fetch and consume the scrape tool's pre-ranked deals

**Status:** Done
**Feature:** F0015 — Weekly Deal Roundup Content
**Spec ref:** `docs/specs/F0015.md` § US00151
**Predecessors:** none — this story is the data-input layer for the rest of F0015.
**Successors:** **US00152** (hard — consumes `RankedDeal[]` from this story), US00153, US00154.

---

## 0. The spec's process flow is not implementable as written — and the repo already has the answer

Spec §3 step 2 says _"The script calls `mcp__shopee-affiliate__scrape_products({ keywords, top_n })`"_. **A `tsx` process cannot call an MCP tool.** MCP tools are exposed to the Claude Code client, not to Node — there is no in-process binding, no HTTP endpoint the script could hit, and adding one would mean building an MCP client into this repo.

This is the same constraint F0012/US00124 hit, and it was already resolved there. `scripts/ingest/sources/scrape.ts`'s doc comment states the resolution as a decision (D1):

> Reads the `data/deals/<date>.json` snapshot already produced out-of-band by the shopee-affiliate scrape tool, run separately beforehand (D1) — **this Node process never invokes that tool itself; the file is the contract.**

`.claude/commands/scrape-ingest.md` § 3 is the other half: the **slash command** (i.e. Claude) calls the MCP tool, which writes `data/deals/<today>.json` itself, and the Node CLI then reads it.

**D1 — F0015 adopts the identical split.** The MCP call belongs to US00154's slash command; this story owns only the read side. Every acceptance criterion still holds: US00151 Scenario 1's _"receives exactly the tool's own ranked/filtered result (no re-sorting, re-filtering, or re-scoring performed in this repo)"_ is in fact **easier** to guarantee reading a file than wrapping a call, and Scenario 1's _"persists nothing beyond what the tool already wrote to `data/deals/<date>.json`"_ becomes true by construction — this story writes nothing at all.

## 1. Scope

1. `scripts/deal-roundup/deal.ts` — the `RankedDeal` model shared by every F0015 module.
2. `scripts/deal-roundup/source.ts` — `loadRankedDeals()`: read snapshot → match keyword → take top N in tool order → `assertAffiliateUrl` per deal → drop + collect failures.
3. `scripts/deal-roundup/args.ts` — `parseDealRoundupArgs()` for `--category`/`--query`/`--top`/`--date`/`--dry-run`.
4. `scripts/deal-roundup/report.ts` — `DealRoundupSummary` + `printDealSummary()` (shortfall footer, dropped-deal group).
5. `scripts/deal-roundup/source.test.ts` + `args.test.ts` — offline, against a committed fixture snapshot.

**Out of scope:** writing any file (that is US00152); calling the MCP tool (US00154); image staging (US00152); any change to `scripts/ingest/**` — the F0012 ingest path is untouched, per spec §6 _"deliberately does not touch `ingest:products`"_.

## 3. Design

### 3.1 `scripts/deal-roundup/deal.ts` — the shared model

```ts
/**
 * A single ranked deal, mapped from the scrape tool's RawDeal.
 *
 * Deliberately NOT the F0012 `Candidate` shape: a Candidate exists to become a
 * `Product` fixture and therefore requires `brand` + `specs`, which the scraper
 * does not reliably populate (deal-schema.ts, confirmed 2026-07-26) — routing
 * around exactly that gap is F0015's entire reason to exist (spec §1). A
 * RankedDeal carries only what a deal card renders.
 *
 * `score` and the source ordering come from the tool's rankDeals(); this repo
 * never recomputes either (spec §2 Out of Scope, US00151 Scenario 1).
 */
export interface RankedDeal {
  /** 1-based position in the tool's own ranking. Never re-derived. */
  rank: number;
  name: string;
  priceVnd: number;
  originalPriceVnd: number;
  discountPercent: number;
  rating: number;
  soldCount: number;
  shopLocation: string;
  isOfficialShop: boolean;
  isFreeShipping: boolean;
  /** Remote CDN URL at this stage. US00152 stages it locally before it is ever rendered. */
  imageUrl: string;
  affiliateUrl: string;
  /** The tool's own score, carried through for the run summary only — never sorted on. */
  score: number;
}

/** A deal excluded from the roundup, with the reason, for the run summary. */
export interface DroppedDeal {
  rank: number;
  name: string;
  reason: string;
}
```

### 3.2 `scripts/deal-roundup/source.ts`

```ts
export interface LoadRankedDealsResult {
  deals: RankedDeal[];
  dropped: DroppedDeal[];
  /** What --top asked for. `deals.length` may legitimately be lower (Scenario 3). */
  requested: number;
  /** Absolute path of the snapshot actually read — echoed in the summary for auditability. */
  snapshotPath: string;
}

export function loadRankedDeals(
  args: DealRoundupArgs,
  opts: { dealsDir?: string } = {},
): LoadRankedDealsResult;
```

Behaviour, step by step:

1. `date = args.date ?? isoToday()`; `file = <dealsDir>/<date>.json`. **Missing file is fatal**, naming the path and telling the operator to run the scrape first — identical wording and rationale to `loadScrapeCandidates` (US00124 D9). A silent empty roundup would be indistinguishable from "no qualifying deals this week", which spec §5 treats as a _different_ outcome.
2. `parseDealsSnapshot(JSON.parse(...), file)` — the runtime shape guard. Malformed snapshot is fatal with a path-named message; F0015 adds no second opinion about the schema.
3. Match `snapshot.results.find(r => r.keyword.trim() === args.query.trim())`. Exact trimmed match, **no fuzzy matching** — same rule `/scrape-ingest` § 2 applies to category resolution ("do not fuzzy-match or guess"). No matching keyword group ⇒ `deals: []`, which flows to the empty-result path, not an error.
4. **`.slice(0, args.top)` and nothing else.** No `sort`, no `filter` on discount/rating/sold, no re-scoring. This single line _is_ Scenario 1; a code comment says so, because it is the kind of line a future contributor "improves" by adding a sort.
5. Map each `RawDeal` → `RankedDeal` with `rank = index + 1` (position in the tool's array).
6. Per deal, in map order:
   - `affiliateUrl === null || ""` ⇒ drop, reason `"no affiliate link resolved by the scrape tool"`. Real snapshots do contain `affiliateUrl: null` (the field is typed `string | null` in `deal-schema.ts`), so this is the common case, not a theoretical one.
   - else `try { assertAffiliateUrl(url, `deal#${rank}`) } catch (e) { drop with e.message }`. **Caught, never propagated** — Scenario 2 requires the rest of the roundup to still generate.
7. Return `{ deals, dropped, requested: args.top, snapshotPath: file }`.

`rank` is preserved from the _pre-drop_ position deliberately: if deal 3 is dropped, the remaining ranks read 1, 2, 4, 5. US00152 renumbers for display; keeping the source rank here makes the summary line up with the raw snapshot an operator may be reading side by side.

### 3.3 `scripts/deal-roundup/args.ts`

```ts
export interface DealRoundupArgs {
  category: string; // required
  query: string; // required
  top: number; // default 5
  date?: string; // default: today
  dryRun: boolean; // default false
}
```

Hand-rolled `--key=value` / `--flag` parser in the same shape as `parseIngestArgs` and `parseScaffoldArgs` — no `commander`/`yargs` dependency, matching the existing scripts. Validation: missing `--category` or `--query` is fatal; `--top` must parse to an integer in `1..10` (the tool's `top_n` default is 10, and a roundup longer than that stops being a roundup); unknown flag is fatal naming the flag.

`assertCategoryRegistered(args.category, "<deal-roundup>")` runs as a **preflight in the CLI entry**, before any file read — mirroring `scripts/scaffold-post.ts:89`. An unregistered category must fail before the operator waits on I/O.

### 3.4 `scripts/deal-roundup/report.ts`

```
Deals (3 of 5 requested):
  1. Bàn Phím Cơ AULA F75 … — ₫699.000 (-66%), 4.6★, 213 đã bán
  2. …
Dropped (2):
  ! deal#3 — <name>: no affiliate link resolved by the scrape tool
  ! deal#5 — <name>: affiliateUrl host "shopee.com.my" is not an allowed Shopee host (…)

snapshot data/deals/2026-09-07.json · keyword "chuột gaming" · requested 5, usable 3
```

The footer's `requested N, usable M` mirrors `printSummary`'s `requested N, ingested M` line — Scenario 3's _"reports the shortfall … rather than failing or fabricating placeholder entries"_. **The exit code stays 0 on a shortfall.** Formatting uses the existing chokepoint `formatVnd` from `lib/format.ts`; `CLAUDE.md` forbids hand-rolling a `₫` string anywhere, and a CLI summary is not an exception.

## 4. Tests — `scripts/deal-roundup/source.test.ts`

Offline, against a committed fixture at `scripts/deal-roundup/__fixtures__/deals-sample.json` (hand-written, mirroring `scripts/ingest/__fixtures__/deals-sample.json`'s precedent). The fixture carries one keyword group with 5 deals: 3 clean, 1 with `affiliateUrl: null`, 1 with a non-allow-listed host.

| Case                         | Expectation                                                                                                                                                                            |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| happy path, `--top=3`        | 3 deals, in **snapshot order**; `ranks === [1,2,3]`                                                                                                                                    |
| ordering is the tool's       | fixture deals are deliberately in a non-monotonic `score` order; assert the result order matches the **file**, not a descending `score` sort (this is the Scenario 1 regression guard) |
| `affiliateUrl: null`         | dropped, reason names "no affiliate link", other deals still returned (Scenario 2)                                                                                                     |
| bad host                     | dropped, reason contains the host and the allow-list, run still succeeds (Scenario 2)                                                                                                  |
| `--top=5` with only 3 usable | `deals.length === 3`, `requested === 5`, no throw (Scenario 3)                                                                                                                         |
| keyword not in snapshot      | `deals: []`, no throw                                                                                                                                                                  |
| missing snapshot file        | throws, message contains the expected path                                                                                                                                             |
| malformed snapshot           | throws from `parseDealsSnapshot`, message names the file                                                                                                                               |

`args.test.ts`: missing `--category`, missing `--query`, `--top=0` / `--top=abc` / `--top=99`, unknown flag, `--date` passthrough, `--top` default of 5.

## 7. Risks & edge cases

- **R1 — A future contributor adds a sort.** The single most likely regression, and invisible in review. Mitigated by the explicit ordering test in §4 plus an in-code comment at the `.slice()`.
- **R2 — `affiliateUrl: null` is the norm, not the exception.** The tool resolves affiliate links only for its top N; a snapshot produced with a larger `top_n` than this run's `--top` may still contain unresolved entries, and re-reading an _older_ snapshot (`--date`) can surface many. The drop path is therefore a routine outcome the summary must present calmly — not an error, not a warning that implies breakage.
- **R3 — Snapshot/`--query` mismatch.** `data/deals/<date>.json` groups by the _exact_ keyword the tool was called with. If US00154's MCP call uses `"chuột gaming không dây"` and the operator later re-runs `--query="chuột gaming"` against the same file, the group silently doesn't match and the roundup is empty. Mitigation: the summary always echoes the snapshot path **and** the keyword (§3.4), and US00154 passes the same string to both sides from one variable.
- **R4 — Stale-snapshot re-runs.** `--date` pointing at last week's file will happily generate "this week's" roundup from stale prices. Not guarded in code (an operator may legitimately want it for a re-run after a crash); documented in `scripts/README.md` and surfaced by the echoed snapshot path.
- **R5 — Shortfall of zero.** `deals.length === 0` is handled here as a normal result; the _decision_ to write nothing and not supersede belongs to US00152/US00154 (spec §5, first bullet). This module must not exit non-zero for it.
