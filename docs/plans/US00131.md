# Implementation Plan — US00131: Clear the catalog launch minimum & clean scraped fixtures

**Status:** Approved
**Feature:** F0013 — Launch Content Remediation
**Spec ref:** `docs/specs/F0013.md` § US00131 · `docs/spec.md` §9
**Predecessors:** none — first story of F0013, because every later story consumes the product slugs and image filenames settled here.
**Sequencing constraint (the other direction):** this story must merge **before** US00135's Half B sets the production domain — slug rewrites are redirect-free only while the site is uncrawled.
**Successors:** US00132 (its stocked/deferred decision depends on the final catalog, and its ≥3-per-category guard needs the grown catalog to pass), US00133 (cover images point at staged product image filenames renamed here), US00134 (`<ProductCard slug>` embeds must reference the final slugs), US00135 (its Half B must not run until these URL changes have landed).

---

## 1. Scope

Strictly:

1. **Grow the catalog** from 10 to **≥14** products via `npm run ingest:products --source=scrape` (the operator's chosen path), prioritising `ban-phim-gaming` (1 product today).
2. **Editorially clean every fixture** — new and existing: `name` (≤~70 chars, brand + model + qualifier, no marketing punctuation/boilerplate), `slug` (≤60 chars), `description` (original Vietnamese, no `"Mô tả chi tiết:"` prefix, no verbatim Shopee block).
3. **Propagate every slug rename atomically**: fixture filename, `slug` field, `images[]` paths, the staged files under `public/static/images/products/`, every `coverImage` in `content/posts/*.mdx`, and every `<ProductCard slug="…">` embed.
4. **Verify every `affiliateUrl` opens the right live Shopee page**; fix or remove dead links.
5. **Add a catalog-quality guard** (`lib/products.test.ts`) so the cleaned state cannot silently regress on the next ingest.

**Explicitly out of scope:**

- Redirects for the renamed product URLs — the site is not indexed under the production domain yet (spec §2).
- Stocking `man-hinh-gaming` / `ghe-gaming` — **US00132** (decided: defer both, so they need no products).
- Cover-image work and the `lib/posts.ts` guard — **US00133**.
- Post prose — **US00134**.
- Changing `scripts/ingest/validate.ts`'s required-field rules to let thin scraped deals through (see **R2** — weakening a guard to hit a count is the wrong trade).

## 3. Approved Decisions

| # | Decision | Choice | Rationale |
| --- | --- | --- | --- |
| D1 | Target count | **≥14** products, `ban-phim-gaming` **≥4** (final ≈ 6 chuột / 3–4 tai nghe / 4–5 bàn phím) | Spec floor is 12/≥3-per-category, but Scenario 5 can *remove* a product for a dead link. A 12-exact catalog breaches the floor the moment one link dies. Two spare units is the cheapest insurance. |
| D2 | Sourcing | `npm run ingest:products -- --source=scrape --category=ban-phim-gaming --query="bàn phím gaming" --count=<n>` against a **fresh, larger** snapshot: re-run the `shopee-affiliate` scrape tool for `bàn phím gaming`, `bàn phím cơ gaming`, `tai nghe gaming` with a high per-keyword count so the ~15% spec-bearing yield still returns ≥4 usable keyboards | The operator chose the scrape path. Yield, not mechanism, is the constraint — solve it with volume + extra keywords. |
| D3 | Fallback if the scrape still yields too few | Ingest the shortfall via `--source=file --path=data/curated/<date>.json`, hand-filling `specs` from the Shopee listing. **Trigger:** after two scrape attempts, `ban-phim-gaming` still < 4 | Keeps the story unblockable without weakening `validateCandidate` (R2). The `file` adapter (US00125) already exists for exactly this. |
| D4 | Editorial cleanup is a **separate commit** from ingestion | Commit 1 = raw ingest output (audit trail of what the pipeline produced); Commit 2 = the editorial pass | Makes the diff reviewable — otherwise "what did the pipeline do" and "what did the human rewrite" are indistinguishable. |
| D5 | Slug format | `<brand>-<model>-<1–2 word qualifier>`, lowercase ASCII, ≤60 chars, e.g. `logitech-g305-lightspeed-wireless`, `razer-deathadder-essential` | Short, stable, reads as a URL; drops the marketing tail that produced 95-char slugs. Category prefix (`chuot-`) is redundant — the category lives in the URL path already. |
| D6 | Rename mechanics | Commit a one-shot dev CLI `scripts/rename-product.ts` (`npm run rename:product -- --from=<old> --to=<new>`) that performs all five renames atomically (fixture file, `slug`, `images[]`, staged image files via `git mv`, and every reference in `content/posts/*.mdx`), refusing to run if the target slug already exists | 12–14 renames × 5 touch-points each is precisely where a silent miss happens. Every future scrape ingest produces raw slugs and needs this again, so it is not throwaway. Follows the `scripts/` convention (tsx, never imported by `next build`). |
| D7 | `description` rewriting | 2–4 sentences of original Vietnamese per product, written by the operator, mentioning the concrete spec that justifies the pick. Never a paraphrase pass over the Shopee block | Scenario 4 is about duplicate content — a reworded copy of the listing is still duplicate-adjacent and adds no value. |
| D8 | `featured` curation | Set `featured: true` on **6** products only (2 per shipping category, spread across price bands); `false` on the rest | Beyond the letter of the AC but squarely in its intent ("does not look like a scraped mirror"). All-10-featured makes `<FeaturedProducts>` (max 8) an arbitrary truncation of the whole catalog. |
| D9 | Guard location | New `lib/products.test.ts` (Vitest), **not** a `next build` throw | Editorial rules (name length, boilerplate words, description prefix) are judgement-shaped; a build-time throw on a punctuation regex would be brittle and would block emergency content edits. Structural rules that *are* build-worthy (image file exists) are picked up by US00133's shared helper. |
| D10 | Affiliate-link verification | Manual: open all ≥14 `affiliateUrl`s in a browser, record pass/fail in the PR body | `s.shopee.vn` short links resolve through JS/app-redirects; an automated `fetch` HEAD check gives false negatives. ≥14 clicks once, before launch, is the honest approach. |

## 5. Step-by-step execution order

1. Branch `feat/US00131`.
2. **Guard first (test-first rule):** write `lib/products.test.ts` (D9) and confirm it **fails today** — it should flag all 10 slugs/names and the boilerplate descriptions. This is the acceptance harness for the whole story.
3. Build the rename CLI: `scripts/rename-product.test.ts` → `scripts/rename-product.ts` until green.
4. **Ingest (commit 1, D4):** run the scrape tool for `bàn phím gaming` + `bàn phím cơ gaming` (+ `tai nghe gaming` for D1 headroom) at a high count → commit `data/deals/<date>.json` → `npm run ingest:products -- --source=scrape --category=… --query=… --count=… --dry-run` first, inspect the summary, then run for real. Repeat per category. If `ban-phim-gaming` < 4 after two attempts, switch to D3's curated-file fallback.
5. **Editorial pass (commit 2, D4):**
   a. For each product, decide the final slug (D5) and run `npm run rename:product -- --from=… --to=…`.
   b. Hand-edit `name` (≤70, no boilerplate) and `description` (D7) in each fixture.
   c. Set `featured` per D8.
   d. Re-run `npm test` until `lib/products.test.ts` is green.
6. **Affiliate-link sweep (D10):** open every `affiliateUrl`; dead link → fix the URL, or delete the fixture + its images + any embed referencing it, then re-check D1's counts still hold.
7. `npm run typecheck && npm run lint && npm test && npm run build`.
8. **Browser verification** (project UI rule): `/san-pham/` grid, 2–3 `/san-pham/<new-slug>/` detail pages, `/danh-muc/ban-phim-gaming/`, the homepage featured strip, and the 3 posts whose embeds moved — confirm images render and no card is broken.
9. Docs + `CLAUDE.md` structure update; PR `feat/US00131` → `main`.

## 9. Risks / open items

- **R1 — Scrape yield (measured ~10–20% ingestable).** The dominant schedule risk. Mitigated by D2 (volume + extra keywords) and bounded by D3 (curated-file fallback after two attempts). Do **not** let this story stall waiting on an upstream scraper fix.
- **R2 — Temptation to relax `validateCandidate`.** Dropping the `specs` requirement would let thin deals in and silently degrade every product detail page's `<dl>`. Explicitly rejected; D3 is the sanctioned escape hatch.
- **R3 — A missed `coverImage` rename does not fail the build today.** US00133's guard closes it, but that lands *after* this story. Mitigated by D6 (the CLI rewrites `coverImage` too) and `lib/products.test.ts` case (f); re-verify after US00133 merges.
- **R4 — Slug-change window closes at US00135 Half B.** Once the real domain is crawled, these renames would need redirects the SSG-only site cannot serve. **Merge US00131 before setting the production domain.**
- **R5 — `git mv` vs. the ingest CLI's refuse-if-exists.** After a rename, re-running the same ingest could re-add the product under its raw slug if the `affiliateUrl` index misses. Dedupe keys on `affiliateUrl` **first**, and renaming never changes `affiliateUrl` — so this is safe by construction. Asserted implicitly by re-running an ingest in step 4 and seeing "skipped-duplicate".
- **R6 — Test-only guards are not yet a CI gate** (F0014/US00143 adds the `test` job). Until then `lib/products.test.ts` protects only local runs; run `npm test` before every content merge.
