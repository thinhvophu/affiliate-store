# Implementation Plan — US00144: `affiliate_click` event tracking on every affiliate link

**Status:** Approved
**Feature:** F0014 — Launch Technical Readiness (**delivers F0007's click-tracking scope**)
**Spec ref:** `docs/specs/F0014.md` § US00144
**Predecessors:** **US00143** (hard dependency — this listener mounts inside the same enabled branch and calls the `gtag` that story loads).
**Successors:** none. With this merged, **F0007 is considered implemented** (spec §1) and gets no separate spec file.

---

## 0. The seam already exists

`components/AffiliateLink.tsx` has emitted the four contract attributes since US00033, and its own doc comment says so:

```
 *   data-affiliate-link              presence flag (selector hook)
 *   data-product-name                from productName prop
 *   data-product-category            from productCategory prop
 *   data-destination-url             from href prop (mirrors the href)
 *
 * Until F0007 ships, the seam is INERT.
```

`CLAUDE.md` declares these a public API and states that renaming any of them is a breaking change that must update both sides in the same PR. **This story is the consumer that finally makes the seam live.** `<AffiliateLink>`, `<ProductCard>`, `<MdxProductCard>`, `<RelatedProducts>`, `<FeaturedProducts>` and every other call site are **not modified** — that is the point of spec §6's _"the click listener is delegated, not per-link… zero changes to consumers. It also keeps `<AffiliateLink>` a Server Component."_

## 1. Scope

1. Extend `lib/analytics.ts` (created by US00143) with the event name, the four attribute names, and a **pure** payload reader.
2. `components/AffiliateClickTracker.tsx` — new `"use client"` component: one delegated `document` listener.
3. Mount it inside US00143's enabled branch in `app/layout.tsx`.
4. Tests: pure-payload unit tests **plus** a contract test that renders `<AffiliateLink>` and asserts it emits exactly the attribute names the listener reads.
5. Structure-doc updates.

**Out of scope:** any change to `<AffiliateLink>` or its consumers; tracking non-affiliate outbound links; `sendBeacon` / `unload` workarounds (spec §6: _"`target="_blank"` removes the hard part… do not add unload-based workarounds"_); custom GA4 dimension registration in the GA console (an operator step, noted in §5).

## 2. Codebase touchpoints

```
│   ├── AffiliateLink.tsx        # Server Component — canonical affiliate-link primitive; baked target/rel + F0003↔F0007 seam attributes (US00031, US00033)
│   ├── layout.tsx               # Root layout … + <GoogleAnalytics /> (US00143)
│   ├── analytics.ts             # (US00143) resolveGaMeasurementId() — server-only analytics gate
```

Conventions honoured: no JSX in `lib/`; `"use client"` only where genuinely required (a `document` listener requires it); `@/*` imports; single chokepoint.

## 3. Design

### 3.1 `lib/analytics.ts` — additions (no JSX, node-testable)

```ts
/** GA4 event name for an outbound affiliate click. */
export const AFFILIATE_CLICK_EVENT = "affiliate_click";

/**
 * The F0003 ↔ F0007 data-* contract, in code.
 *
 * These MUST match the attributes written by <AffiliateLink> exactly.
 * CLAUDE.md: renaming any of them is a breaking change that must update both
 * sides in the same PR. `lib/analytics.test.ts` renders <AffiliateLink> and
 * asserts the two sides agree, so drift fails the build instead of silently
 * shipping events with undefined fields (spec §5).
 */
export const AFFILIATE_LINK_SELECTOR = "[data-affiliate-link]";
export const AFFILIATE_DATA_ATTRIBUTES = {
  productName: "data-product-name",
  productCategory: "data-product-category",
  destinationUrl: "data-destination-url",
} as const;

export interface AffiliateClickPayload {
  product_name: string;
  product_category: string;
  destination_url: string;
}

/** Minimal structural type — keeps this function testable in the node env. */
type AttributeSource = { getAttribute(name: string): string | null };

/**
 * Read the GA4 payload off a matched affiliate anchor.
 * Returns null when the element carries none of the contract attributes, so a
 * future markup change degrades to "no event" rather than an event full of
 * undefined fields.
 */
export function readAffiliateClickPayload(
  el: AttributeSource | null,
): AffiliateClickPayload | null {
  if (!el) return null;
  const product_name = el.getAttribute(AFFILIATE_DATA_ATTRIBUTES.productName);
  const product_category = el.getAttribute(AFFILIATE_DATA_ATTRIBUTES.productCategory);
  const destination_url = el.getAttribute(AFFILIATE_DATA_ATTRIBUTES.destinationUrl);
  if (product_name === null && product_category === null && destination_url === null) {
    return null;
  }
  return {
    product_name: product_name ?? "",
    product_category: product_category ?? "",
    destination_url: destination_url ?? "",
  };
}
```

Putting the reader in `lib/` (pure, DOM-free by structural typing) is what lets the whole payload path be tested in the existing `environment: "node"` vitest setup — **no `jsdom` devDependency is added.** See D3.

### 3.2 `components/AffiliateClickTracker.tsx` (new, `"use client"`)

```tsx
"use client";

import { useEffect } from "react";
import {
  AFFILIATE_CLICK_EVENT,
  AFFILIATE_LINK_SELECTOR,
  readAffiliateClickPayload,
} from "@/lib/analytics";

declare global {
  interface Window {
    gtag?: (command: "event", name: string, params?: Record<string, unknown>) => void;
  }
}

/**
 * F0007's delegated affiliate-click listener — the consumer of the
 * F0003 ↔ F0007 data-* contract documented on <AffiliateLink>.
 *
 * ONE listener on document, not one per link: `closest()` resolves any click
 * inside a whole-card anchor (US00032) to exactly one anchor, so clicking the
 * image, the body or the CTA span sends exactly one event (Scenario 4).
 *
 * Renders nothing. Mounted only when analytics is enabled, so with no
 * measurement ID this component is never in the tree (Scenario 3).
 */
export function AffiliateClickTracker() {
  useEffect(() => {
    function onClick(event: MouseEvent) {
      const target = event.target;
      if (!(target instanceof Element)) return;
      const anchor = target.closest(AFFILIATE_LINK_SELECTOR);
      const payload = readAffiliateClickPayload(anchor);
      if (!payload) return;
      window.gtag?.("event", AFFILIATE_CLICK_EVENT, payload);
    }
    document.addEventListener("click", onClick);
    return () => document.removeEventListener("click", onClick);
  }, []);

  return null;
}
```

Every acceptance criterion maps to a specific line:

- **Scenario 2 (never blocks/delays):** no `preventDefault`, no `await`, no `return false`; `window.gtag?.(…)` is fire-and-forget and optional-called, so an absent or throwing-to-load GA cannot interrupt the default navigation. The anchor's `target="_blank"` keeps the document alive, so no beacon transport is needed.
- **Scenario 3 (silent no-op):** two independent guards — the component is not mounted at all when `resolveGaMeasurementId()` returns `undefined`, and `window.gtag?.` no-ops even if it somehow were.
- **Scenario 4 (exactly one event):** `closest()` returns at most one ancestor per click. Bubbling phase, one listener, no per-link handlers ⇒ no duplication.
- Listener is **not** `capture`, **not** `once`, and is removed on unmount.

### 3.4 Tests — `lib/analytics.test.ts` (extend)

**Pure payload tests** (node env, plain object stubs):

| Case                                              | Expectation                                     |
| ------------------------------------------------- | ----------------------------------------------- |
| all three attributes present                      | payload with the three snake_case GA4 keys      |
| `null` element (click outside any affiliate link) | `null`                                          |
| element with none of the attributes               | `null`                                          |
| element missing one attribute                     | that key is `""`, no `undefined` in the payload |
| Vietnamese diacritics in `product_name`           | round-trip verbatim                             |

**Contract test — the spec §5 "cheap reinforcement".** Verified viable at planning time: `react-dom/server`'s `renderToStaticMarkup` renders `<AffiliateLink>` inside the existing `environment: "node"` vitest config with no new dependency (confirmed by a scratch run, 186 → passing).

```ts
const html = renderToStaticMarkup(
  <AffiliateLink href="https://shope.ee/x" productName="Chuột Logitech G102"
                 productCategory="chuot-gaming">Mua ngay</AffiliateLink>,
);
// the selector the listener uses must actually match what the primitive writes
expect(html).toContain("data-affiliate-link");
for (const attr of Object.values(AFFILIATE_DATA_ATTRIBUTES)) {
  expect(html).toContain(`${attr}=`);
}
// and the payload read back from the rendered markup must be complete
```

This is the guard against spec §5's _"`data-*` contract drift… events keep firing with `undefined` fields rather than throwing."_ Renaming an attribute on either side now fails `npm test` — which, thanks to **US00141**, fails the PR.

The test file must be `.tsx` if it contains JSX; name it `lib/analytics.test.tsx`, or keep `.ts` and call `AffiliateLink({...})` as a plain function (both work — the scratch run used the latter). Prefer `.tsx` + JSX for readability; confirm `tsconfig`/vitest resolve it (they will — `vitest.config.ts` has the `@` alias and Vite handles TSX natively).

### D3 — No `jsdom`, and what that costs

The delegated listener itself (`addEventListener` → `closest` → `gtag`) is **not** unit-tested; only the pure payload reader and the attribute contract are. Adding `jsdom` as a devDependency plus a per-file `// @vitest-environment jsdom` docblock would cover Scenario 4 mechanically.

Recommendation: **skip jsdom.** The untested surface is ~10 lines of glue whose correctness rests on `closest()` semantics, the repo has zero DOM tests today, and the user's own standing rule already requires browser verification for UI work (§4 step 6) — which tests Scenario 4 _in a real browser_, which is stronger evidence than jsdom for this particular claim. **Flagged for Anh Thịnh's call**; if jsdom is wanted, it is a small additive change to this plan, not a redesign.

## 6. Risks & edge cases

- **R1 — Under-counting is accepted, double-counting is not.** Spec §5: middle-click, ⌘/Ctrl-click and context-menu "open in new tab" do not all fire a `click`. Auxiliary clicks are deliberately **not** handled (`auxclick` is not listened for) — adding it would risk double-firing on browsers that emit both. Documented, not fixed.
- **R2 — Ad blockers.** `affiliate_click` totals are a **lower bound** and must not be reconciled against Shopee's dashboard as if authoritative (spec §5).
- **R3 — Contract drift.** Mitigated by the §3.4 contract test — the first real enforcement of a rule that until now was prose in `CLAUDE.md`.
- **R4 — A second `data-affiliate-link` emitter.** `CLAUDE.md` forbids it; the delegated selector would happily track it. Optional hardening: a test asserting `grep -rl 'data-affiliate-link' components/ app/` returns only `AffiliateLink.tsx` and the tracker. Cheap; recommended.
- **R5 — `SpeedInsights` coexistence.** Unrelated listener, no interaction. No change needed.
