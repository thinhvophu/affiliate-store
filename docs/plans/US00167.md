## 1. Decisions

- **D1 — guides vs roundups is decided in `lib/roundups.ts`.** New `getCategoryGuides(posts, category)` returns the non-roundup posts in that category, newest first. A second new function, `prioritizeGuides(posts)`, is a stable partition that puts guides before roundups. `lib/posts.ts` stays unaware of F0015/F0016 (the US00153 rule).
- **D2 — related posts rank guides first at the call site:** `getRelatedPosts(post, prioritizeGuides(all))`. `getRelatedPosts()` filters by category while keeping order, then takes 3, so guides fill the slots first. It's the same call-site pattern `demoteArchivedRoundups` used, and `getRelatedPosts()` itself doesn't change.
- **D3 — the product→posts index lives in `lib/post-embeds.ts`** (Scenario 5). `extractProductEmbeds(content)` returns unique slugs in first-seen order. `getPostsEmbeddingProduct(slug, posts)` returns each post once, newest first. `scripts/sync-content-queue.ts` switches to `extractProductEmbeds()` so the `<ProductCard slug>` regex exists in one place only.
- **D4 — one shared component, `<CategoryGuides>`, for category pages and deal pages.** Props are `{ heading, guides, dealPost?, categoryLink? }`. A category page passes `dealPost`, and a deal page passes `categoryLink`. It renders `null` when it has nothing to show (spec §5: no empty headings). Guides are shown as a compact link list (title, date and summary), not the full `PostCard` grid, so the section stays secondary to the product grid.
- **D5 — placement:**
  - Category page: below the product grid. The 100–200-word intro stays above the grid, as SEO rules require.
  - Deal page: after the body, before related posts.
  - Guide → deal callout `<DealPageLink>` ("Xem deal tuần này"): after the body, before related posts.
  - Product page: "Bài viết nhắc đến sản phẩm này", between the product details and `<RelatedProducts>`.
- **D6 — all links are literal no-slash paths**, `/bai-viet/${slug}` and `/danh-muc/${slug}` (US00161 D3). The new components are server components, but literals keep the same rule everywhere, and the US00161 guard covers them.

## 3. Design

### 3.1 `lib/post-embeds.ts`

```ts
const PRODUCT_CARD_RE = /<ProductCard\s+slug="([^"]+)"/g;
export function extractProductEmbeds(content: string): string[]; // unique, first-seen order
export function getPostsEmbeddingProduct(productSlug: string, posts: Post[]): Post[]; // each once, newest first
```

It takes `posts` as a parameter and doesn't import `lib/posts.ts`, so the fixture tests are simple and nothing ends up in an import cycle. Pages pass `getAllPosts()`. It is called once per product page, so the cost is a regex over 7 posts and there is nothing to memoise.

### 3.2 Components

- `CategoryGuides`: `<section aria-labelledby>` with an `<h2>`. Inside it: a `<ul>` of guide links when there are guides, a deal link row "Deal {category} tuần này →" when `dealPost` is set, and a "Xem tất cả sản phẩm {category} →" link when `categoryLink` is set. All headings sit under the page's single `h1`.
- `DealPageLink`: an inline callout, `<aside><Link href="/bai-viet/deal-<cat>">Xem deal {category} tuần này</Link></aside>`. It's `null` when the category has no roundup.
- `PostsMentioningProduct`: an `<h2>Bài viết nhắc đến sản phẩm này</h2>` and a `<ul>` of post links. It's `null` when the list is empty.

Styles follow the token-based, low-noise look of `CategoryNav`, `RelatedPosts` and `AffiliateDisclosure`.

### 3.3 Page wiring

```ts
// danh-muc/[category]
const posts = getAllPosts();
<CategoryGuides heading="Hướng dẫn chọn mua" guides={getCategoryGuides(posts, slug)}
                dealPost={getRoundupForCategory(posts, slug)} />

// bai-viet/[slug]
const roundup = isRoundupPost(post);
const related = getRelatedPosts(post, prioritizeGuides(all));
roundup
  ? <CategoryGuides heading={`Hướng dẫn chọn mua ${cat.name.toLowerCase()}`} guides={getCategoryGuides(all, post.category)}
                    categoryLink={{ href: `/danh-muc/${post.category}`, label: cat.name }} />
  : <DealPageLink dealPost={getRoundupForCategory(all, post.category)} categoryName={cat.name} />

// san-pham/[slug]
<PostsMentioningProduct posts={getPostsEmbeddingProduct(product.slug, getAllPosts())} />
```

On a deal page the related posts end up guides-only anyway, because the category has a single roundup and the current post is excluded. That can repeat the guides listed in `CategoryGuides`. To avoid showing the same posts twice, **a roundup page drops related posts that already appear in `CategoryGuides`**. If that leaves related posts empty, `RelatedPosts` already returns `null`.
