# Implementation Plan — US00162: One evergreen deal URL per category

**Status:** Approved
**Feature:** F0016 — Traffic Foundations
**Spec ref:** `docs/specs/F0016.md` § US00162
**Predecessors:** US00161 (link form).
**Successors:** **US00163 (hard — merge immediately after this one)**, US00165 (history hooks into the same generator), US00167 (links to the fixed URL).

---

## 0. What changes

F0015 writes `deal-<category>-<date>` every week and supersedes the previous one. F0016 replaces that with **one post per category at `deal-<category>`**, overwritten in place, with an `updatedAt` freshness signal. Supersession has nothing left to do and is removed.

## 1. Decisions

- **D1 — the roundup slug is derived in one place: `roundupSlugFor(category)` in `lib/roundups.ts`** → `` `deal-${category}` ``. The generator, US00163's redirect guard and US00167's links all call it.
- **D2 — `publishedAt` is read back from the existing post.** The generator parses `content/posts/deal-<category>.mdx` (gray-matter) if it exists and keeps its `publishedAt`; otherwise `publishedAt = date` (Scenario 3). `updatedAt = date` on every run.
- **D3 — staged images keep a dated filename: `deal-<category>-<date>-<n>.<ext>`; deal ids are `deal-<category>-<n>`.** Reusing `deal-<category>-<n>.jpg` week after week would serve last week's picture from browser / CDN / `next/image` optimizer caches under an unchanged URL. A dated filename is a free cache-buster, and it is byte-identical to the naming the 2026-10-12 images already use, so US00163 needs no image renames. The `stageImages()` slug argument becomes `` `${postSlug}-${date}` ``; the deal `id` stays `` `${postSlug}-${n}` `` (what `lib/deals.ts`'s `^<basename>-\d+$` check requires).
- **D4 — unreferenced deal images are pruned after every successful run.** With D3, each run orphans last week's 5 images. New `scripts/deal-roundup/image-gc.ts` → `findUnreferencedDealImages({ imagesDir, dealsDir, postsDir })` returns every file in `public/static/images/deals/` that no sidecar `image`, no post `coverImage` and no MDX body references. The generator deletes them after the post + sidecar are written and prints the list. Recoverable: they are tracked files, so the `/deal-roundup` abort path (`git checkout -- content/ public/`) restores them. US00163 reuses the same helper for its one-time cleanup.
- **D5 — the `{/* roundup-lead:… */}` markers are dropped from the template.** Their only consumer was `supersede.ts`. `countWords()` keeps stripping `{/* */}` comments (the TODO markers still use them).
- **D6 — `formatArchiveDate()` is removed** (only `supersede.ts` used it) together with its `lib/format.test.ts` cases.
- **D7 — `lib/roundups.ts` shrinks to: `roundupSlugFor()`, `isRoundupPost()`, `getRoundupForCategory(posts, category)`, `assertOneRoundupPerCategory(posts)`.** `currentRoundupSlugs()` / `demoteArchivedRoundups()` and their call sites in `app/page.tsx` and `app/bai-viet/[slug]/page.tsx` go (Scenario 4). The _live-content_ invariant test (every roundup's slug equals `roundupSlugFor(category)`) lands in **US00163**, because the 10 dated roundups still exist when this PR merges; this PR tests the helper on fixtures only.
- **D8 — `updatedAt` validation lives in `lib/posts.ts`.** Optional; when present it must match `YYYY-MM-DD` and be `>= publishedAt`, else `getAllPosts()` throws naming the slug (spec §5).

> **Merge note:** between this PR and US00163, the dated roundups lose their homepage/related-posts demotion. Merge US00163 right after, and do **not** run `/deal-roundup` in between.

## 3. Design

### 3.1 Types & loader

```ts
// types/post.ts
export interface PostFrontmatter { …; updatedAt?: string }
```

`lib/posts.ts` → `validatePostFrontmatter` adds the D8 check; `posts.push({ …, updatedAt })` only when present.

### 3.2 Post page header

```tsx
<time dateTime={post.publishedAt}>{formatPostDate(post.publishedAt)}</time>;
{
  post.updatedAt && (
    <span className={styles.updated}>
      Cập nhật ngày <time dateTime={post.updatedAt}>{formatPostDate(post.updatedAt)}</time>
    </span>
  );
}
```

`formatPostDate("2026-10-19")` = `"19 tháng 10, 2026"` → "Cập nhật ngày 19 tháng 10, 2026" (Scenario 2). New `.updated` class in `post-detail.module.css`, matching `.readTime`.

### 3.3 Article JSON-LD & sitemap

`dateModified: post.updatedAt ?? post.publishedAt`; `lastModified: new Date(post.updatedAt ?? post.publishedAt)`.

### 3.4 Generator flow (`scripts/generate-deal-post.ts`)

1. args → preflight → `loadRankedDeals()` → summary (unchanged). Zero deals ⇒ print, exit 0, write nothing (Scenario 5).
2. `postSlug = roundupSlugFor(category)`; `publishedAt = readExistingPublishedAt(postPath) ?? date`; `updatedAt = date`.
3. `--dry-run` prints the would-be paths and the `publishedAt`/`updatedAt` it would write.
4. `stageImages(pseudoCandidate, `${postSlug}-${date}`, …)` (D3).
5. Cover floor check (unchanged).
6. Deal ids `${postSlug}-${i + 1}`; `writeDealSidecar(postSlug, …)` (overwrites).
7. `renderDealPostStub({ …, publishedAt, updatedAt })` → write (overwrites).
8. `findUnreferencedDealImages()` → unlink each, print `[deal-roundup] pruned <n> unreferenced image(s)`.

No supersede step.

### 3.5 `scripts/deal-roundup/existing.ts`

`readExistingPublishedAt(postPath: string): string | undefined` — missing file ⇒ `undefined`; unparsable frontmatter or missing `publishedAt` ⇒ throw naming the path (never silently reset the date).

### 3.6 `scripts/deal-roundup/image-gc.ts`

Pure over a directory triple (injectable for tests). Referenced set = all sidecar `image` values ∪ all post `coverImage` values ∪ every `/static/images/deals/…` substring in MDX bodies. Returns absolute paths of files in `imagesDir` not in that set. Reads sidecars as raw JSON (no `lib/deals.ts` validation, so a GC run can't be blocked by an unrelated bad sidecar — but it never writes one either).

> This is the one place outside `lib/deals.ts` that reads sidecar JSON. It reads only the `image` field and never validates or interprets deals — call that out in the module doc and the CLAUDE.md convention, or route it through `getAllDeals({ dealsDir })` if the reviewer prefers strictness. **Recommendation: use `getAllDeals()`** — stricter, and keeps the "no file outside `lib/deals.ts` reads a sidecar" rule literally true.

2. `types/post.ts` + `lib/posts.ts` validation → `article-schema.ts` → `sitemap.ts` → post page header.
3. `lib/roundups.ts` reduction + remove call sites; delete `formatArchiveDate`.

5. Docs: `.claude/commands/deal-roundup.md` (no supersede step; browser check opens `/bai-viet/deal-<category>`; step-7 path list becomes `content/posts/deal-<category>.mdx` (new or modified), `content/deals/deal-<category>.json`, new `public/static/images/deals/deal-<category>-<date>-*`, deleted prior images, `data/deals/<today>.json`; commit message drops "superseded"; remove the lead-marker rule), `scripts/README.md`.

7. Dry-run rehearsal on a scratch branch: `npm run generate:deal-post -- --category=chuot-gaming --query="Chuột gaming" --date=2026-10-12` against the committed snapshot → inspect output, browser-check `/bai-viet/deal-chuot-gaming` (header shows both dates, deal cards render), then discard (`git checkout -- . && git clean -fd content public`). Do not commit that output — US00163 does the real seeding.
