# Implementation Plan — US00147: Generate the current week's deal-roundup post

**Status:** Approved
**Feature:** F0015 — Weekly Deal Roundup Content
**Spec ref:** `docs/specs/F0015.md` § US00147
**Predecessors:** **US00146 (hard)** — consumes `loadRankedDeals()`'s `RankedDeal[]`.
**Successors:** US00148 (builds `lib/roundups.ts` on this story's `lib/deals.ts`), US00149.

---

## 0. The two decisions spec §6 deferred

Spec §6 leaves deal-data persistence open: _"embed the deal data directly in the post's frontmatter, or persist a small per-post JSON sidecar under `content/`"_.

**D2 — Sidecar JSON, loaded by a new `lib/deals.ts` chokepoint.** Approved 2026-09-07. Rationale:

- Frontmatter would require `PostBody` to thread frontmatter into `evaluate()`'s `scope` so `<DealCard>` could read it — new plumbing on the one code path every post already depends on, for the benefit of four posts.
- `types/post.ts` + `validatePostFrontmatter` would grow a `deals` field that 95% of posts never carry.
- A sidecar makes the deal-card adapter an **exact structural copy** of `MdxProductCard` (`getDealById(id)` ↔ `getProductBySlug(slug)`, throw-on-miss either way), which is the pattern the codebase already teaches.
- The sidecar's _existence_ doubles as the "this post is a roundup" marker, which is what lets US00148 satisfy spec §6's _"no new post status field, no CMS-like state machine"_ without inventing one.

**D8 — The generator emits a buildable, real-titled skeleton; a human (US00149's slash command) writes the prose.** Approved 2026-09-07. A generator cannot produce 800 words of genuine Vietnamese copy, and templating its way to the floor would make `MIN_POST_WORDS` stop meaning "publish-grade" — the exact failure `US00134` exists to prevent. This mirrors `scaffold:post` → `/write-post` precisely.

**Consequence for Scenario 3.** Read literally, _"Given the generated post … Then it clears `MIN_POST_WORDS`"_ would demand the generator alone clear 800 words. Under D8 the _committed_ post clears it, with real copy, before `npm run build` runs (US00149 § ordering). The freshly generated stub does **not**, exactly as a `scaffold:post` stub does not — and for the same reason. Everything else in Scenario 3 (≥2 `h2`, ≥1 qualifying embed, both disclosures) **is** satisfied by the generator's output alone.

## 3. Design

### 3.1 `types/deal.ts`

```ts
/**
 * A deal as persisted in a roundup post's sidecar, `content/deals/<post-slug>.json`.
 *
 * Distinct from `Product` by design (F0015 §1): no `brand`, no `specs`, no
 * `slug`, no `description` — the scrape tool populates none of them reliably,
 * and requiring them is precisely what blocks timely deal content today.
 * Distinct from `scripts/deal-roundup/deal.ts`'s `RankedDeal` too: by the time
 * a Deal exists, its image has been staged locally and it has a stable id.
 */
export interface Deal {
  /** `<post-slug>-<n>`, 1-based, unique across all sidecars. The MDX embed key. */
  id: string;
  name: string;
  priceVnd: number;
  /** Equal to `priceVnd` when the tool reports no separate list price — see D5c. */
  originalPriceVnd: number;
  discountPercent: number;
  rating: number;
  soldCount: number;
  /** Root-relative `/static/images/deals/…` ONLY. A remote URL here is a build error. */
  image: string;
  affiliateUrl: string;
  /** The registered category slug — feeds `data-product-category` on the card. */
  category: string;
}
```

Exported from `types/index.ts`; consumers import `{ Deal } from "@/types"` per the barrel convention.

### 3.2 `lib/deals.ts` — the loader chokepoint

```ts
export function getAllDeals(): Deal[]; // every sidecar, flattened, memoised
export function getDealById(id: string): Deal | null;
export function getDealsForPost(postSlug: string): Deal[]; // in id order
export function postHasDeals(postSlug: string): boolean;
```

Reads `content/deals/*.json`; each file is a JSON array of `Deal`. Per deal, at load time:

1. Required fields present and correctly typed; `id` matches `^<file-basename>-\d+$`; ids unique across **all** files.
2. **`assertAffiliateUrl(deal.affiliateUrl, deal.id)`** — spec §6 claims _"`assertAffiliateUrl` gate has no natural call site for deal data"_. **D4 corrects this:** `lib/deals.ts` _is_ the natural call site, exactly as `lib/products.ts` is for fixtures. The generation-time check (US00146) protects the _run_; this one protects the _build_, so a hand-edited sidecar cannot smuggle a bad host into a rendered page. Both are kept.
3. **`deal.image` must start with `/static/`** — reject any `http(s)://` value. Defense-in-depth mirroring `scripts/ingest/writer.ts`'s identical guard, and the enforcement behind `CLAUDE.md`'s _"never hotlinked, ever"_.
4. `assertCategoryRegistered(deal.category, deal.id)`.

Memoised per process (module-level `Map`), same shape as `lib/image-meta.ts`'s per-path memo — `getDealById` is called once per embed during MDX evaluation and would otherwise re-read the directory each time.

`content/deals/` missing entirely ⇒ `[]`, never a throw. The directory does not exist until the first roundup ships, and `npm run build` must not depend on it.

### 3.3 `components/DealCard.tsx`

Server Component, `{ deal: Deal }`, structurally a sibling of `ProductCard`:

```tsx
<AffiliateLink
  className={`${affiliateStyles.card} ${styles.card}`}
  href={deal.affiliateUrl}
  productName={deal.name}
  productCategory={deal.category}
>
  <div className={styles.imageFrame}>
    <Image
      src={deal.image}
      alt={deal.name}
      fill
      sizes="(min-width: 768px) 50vw, 100vw"
      className={styles.image}
    />
    {deal.discountPercent > 0 && (
      <span className={styles.discountBadge}>-{deal.discountPercent}%</span>
    )}
  </div>
  <h3 className={styles.name}>{deal.name}</h3>
  <p className={styles.priceRow}>
    <span className={styles.price}>{formatVnd(deal.priceVnd)}</span>
    {deal.originalPriceVnd > deal.priceVnd && (
      <s className={styles.originalPrice}>{formatVnd(deal.originalPriceVnd)}</s>
    )}
  </p>
  <p className={styles.social}>
    {deal.rating.toFixed(1)}★ · {deal.soldCount} đã bán
  </p>
  <span data-affiliate-cta className={styles.cta}>
    Xem deal
  </span>
</AffiliateLink>
```

**Scenario 2 is satisfied by construction, not by new code.** Every contract attribute (`data-affiliate-link`, `data-product-name`, `data-product-category`, `data-destination-url`) is emitted by `<AffiliateLink>` itself; `AffiliateClickTracker`'s delegated `closest("[data-affiliate-link]")` therefore matches a deal card with **zero** changes to `lib/analytics.ts` or the tracker (spec §6, Relationship to F0014). The `CLAUDE.md` rule _"No other component in the codebase may emit `data-affiliate-link`"_ is respected: `DealCard` emits none itself, it delegates.

Whole-card rules from `US00032` apply unchanged: no nested `<a>`, no `<button>`; the CTA is a `<span data-affiliate-cta>`.

`formatVnd` is used for **both** prices — `CLAUDE.md` forbids any other file formatting a `₫` value. Rating is `toFixed(1)`, which is not an `Intl` call and is deterministic across build pools.

**D5c — guard the strikethrough.** Real snapshot data (`data/deals/2026-08-22.json`, deal 1) carries `priceVnd === originalPriceVnd === 699000` alongside `discountPercent: 66`. Rendering `<s>₫699.000</s>` next to `₫699.000` would look broken and arguably misleading, so the strikethrough renders only when `originalPriceVnd > priceVnd`. The badge still shows the tool's `discountPercent` — this repo treats the tool's numbers as authoritative (spec §5, last bullet) and does not recompute a discount from the two prices.

### 3.4 `components/MdxDealCard.tsx` + map entry

```tsx
export function MdxDealCard({ id }: { id: string }) {
  const deal = getDealById(id);
  if (!deal) {
    throw new Error(
      `[mdx DealCard] <DealCard id="${id}" />: no deal matches this id in content/deals/.`,
    );
  }
  return <DealCard deal={deal} />;
}
```

Registered as `DealCard: MdxDealCard` in `getMdxComponents()`. Confirmed against the bundled docs for the installed Next.js **16.2.10** (`node_modules/next/dist/docs/01-app/02-guides/mdx.md` § "Using custom styles and components"): a component map entry is the supported extension point, and this adds **no new Next.js API surface** — no new route, no config change, no `remotePatterns`.

Same author-facing/implementation name split `MdxProductCard` documents (`D2` there): the MDX tag `DealCard` maps to `MdxDealCard`; the prop-based `DealCard` is never exposed to MDX authors, so the two identifiers never collide in imports.

### 3.6 Generation

**`scripts/deal-roundup/template.ts` — `renderDealPostStub()`**, pure, no I/O (same contract as `scripts/scaffold/template.ts`).

```mdx
---
title: "Top 5 deal chuột gaming trên Shopee tuần này"
summary: "Tổng hợp 5 deal chuột gaming đang giảm giá mạnh trên Shopee tuần này, kèm giá, mức giảm và đánh giá thực tế."
publishedAt: "2026-09-07"
category: "chuot-gaming"
tags: ["deal shopee", "chuột gaming", "khuyến mãi"]
coverImage: "/static/images/deals/deal-chuot-gaming-2026-09-07-1.jpg"
---

{/* roundup-lead:start */}
Tuần này chúng tôi chọn ra 5 deal chuột gaming đáng chú ý nhất trên Shopee, dựa trên mức giảm giá, điểm đánh giá và lượt bán thực tế.
{/* roundup-lead:end */}

## Top 5 deal chuột gaming tuần này

### 1. <deal name>

<DealCard id="deal-chuot-gaming-2026-09-07-1" />

{/* TODO: viết nhận xét ngắn cho deal này */}

…

## Lưu ý khi săn deal trên Shopee

{/* TODO: viết phần lưu ý mua hàng */}
```

Four things the template must get right:

- **The title is real, not a `TODO`.** US00148 Scenario 1 requires the H1 to read _"… Tuần Này"_, so the evergreen framing is generated content, not a placeholder. Likewise `summary` (a genuine 50–160-char sentence) and `tags` (non-empty) — all three are checked by `lib/posts.test.ts` and all three are deterministic from `(count, category, date)`. Only the **body prose** carries `TODO` markers.
- **The category label comes from `getCategoryMeta()`**, not from `--query`. `CLAUDE.md`: _"No file outside `lib/categories.ts` may parse, normalize, or ad-hoc look up category metadata."_ `--query` is free-text operator input and unfit for a title; the registered display name is human-reviewed. (Spec §2 writes `<keyword>`; this is the same intent, sourced from the registry.)
- **Exactly two `h2` sections**, satisfying the `US00134` TOC guard from the generator alone. Per-deal headings are `h3` so they nest correctly under the TOC's h2/h3 model (`lib/toc.ts` reads depth 2 and 3 only).
- **The `{/* roundup-lead:… */}` markers** delimit the lead paragraph so US00148 can rewrite it deterministically even after a human rewrites everything around it. `{/* … */}` is a JSX expression comment — valid MDX v3, renders nothing. (HTML `<!-- -->` comments are **not** valid in MDX v3 and must not be used.)

**`scripts/deal-roundup/writer.ts`** serializes `Deal[]` to `content/deals/<post-slug>.json`, pretty-printed, and re-asserts `image.startsWith("/static/")` before writing — the same refuse-to-write-a-remote-URL guard `scripts/ingest/writer.ts` carries.

**`scripts/generate-deal-post.ts`** — CLI entry, `npm run generate:deal-post`:

1. `parseDealRoundupArgs` → `assertCategoryRegistered` (preflight, before I/O).
2. `loadRankedDeals(args)` (US00146).
3. **Zero usable deals ⇒ print the summary, exit 0, write nothing.** Spec §5 first bullet. The caller (US00149) reads this as "do not supersede".
4. `postSlug = "deal-" + category + "-" + date`.
5. **Stage images — one `stageImages()` call for the whole roundup.** Pseudo-candidate `{ imageUrls: deals.map(d => d.imageUrl), sourceRef: postSlug, name: postSlug }`, `slug = postSlug`, `destDir = public/static/images/deals`, producing `deal-chuot-gaming-2026-09-07-1.jpg … -5.jpg` in rank order. **D5b — staging is all-or-nothing for the roundup**, inheriting `stageImages`' per-candidate atomicity: any 404/timeout/bad-content-type aborts the run **before any post or sidecar is written**, so a post can never reference a missing image. Re-running is cheap because staging is idempotent (already-staged files are skipped, not re-fetched).
   _Verified against real data:_ Shopee CDN URLs (`https://down-vn.img.susercontent.com/file/vn-…`) carry **no file extension**, so `extFromUrl` returns `undefined` and the existing `Content-Type` fallback is the path that fires. This is already-exercised code, not a new branch.
6. **Cover image floor.** `readImageSize()` each staged path; `coverImage` = the first clearing `MIN_COVER_IMAGE_SHORT_SIDE_PX` (600). **If none clears it, exit non-zero before writing the MDX**, naming the paths and sizes. Otherwise `lib/posts.ts`'s `assertMinShortSide` would fail the _build_ later with a message that says nothing about deal roundups. (Sampled staged Shopee images are 1000–1024px, so this is a guard, not an expected path.)
7. Build `Deal[]` (local image paths, ids `<postSlug>-<n>`, `category` from `--category`) → write the sidecar → write the MDX.
8. Print the run summary including both written paths.

`--dry-run` prints the summary and the would-be paths and **stages nothing, writes nothing.**

**D6 — `generate:deal-post` overwrites; `scaffold:post` refuses to.** A deliberate, documented divergence. Spec §5 requires _"the second run's 'current' post overwrites the first run's 'current' post output for that day rather than creating a second archived entry"_ — an operator fixing a keyword typo must be able to re-run. Because the slug carries the date, "overwrite" is scoped to _today's_ post for _this_ category and can never clobber a prior week's. Both written paths are echoed so an overwrite is visible in the summary, and `git status` shows it as a modification.

### 3.7 Guard edits

**`lib/posts.test.ts`** — spec §6's required edit:

```ts
it("every post embeds at least one <ProductCard slug=…> or <DealCard id=…>", () => {
  for (const post of posts) {
    const productEmbeds = post.content.match(/<ProductCard\s+slug="/g) ?? [];
    const dealEmbeds = post.content.match(/<DealCard\s+id="/g) ?? [];

      productEmbeds.length + dealEmbeds.length,

```

**`lib/format.ts` — `countWords()` strips `{/* … */}`.** Added here rather than in US00148 because this story is what puts MDX comments into committed post bodies. Without it, the lead markers and any leftover authoring comments count as prose and _inflate_ the word count — weakening the depth floor in the wrong direction. One line, in the project's word-counting chokepoint, before the existing tag strip:

```ts
.replace(/\{\/\*[\s\S]*?\*\/\}/g, "")
```

`readingTimeVi` shares `countWords`, so read-time estimates get marginally more accurate too; `lib/format.test.ts` gains a case asserting a comment contributes zero words. (Noted as a deviation from the approved outline, which placed this in US00148.)

New **module convention** paragraphs for `CLAUDE.md`:

> **Deal data lives in one place: `lib/deals.ts`.** Roundup deals are persisted as a per-post sidecar `content/deals/<post-slug>.json` (F0015/US00147, decision D2) — never as `content/products/*.json` fixtures, which would re-impose the `brand`/`specs` requirement this feature exists to route around. No file outside `lib/deals.ts` may read or parse a sidecar. The loader calls `assertAffiliateUrl()` and `assertCategoryRegistered()` per deal and rejects any non-root-relative `image`, so a hand-edited sidecar fails `next build` with the offending deal id named — the same fail-loudly discipline `lib/products.ts` applies to fixtures.
>
> **MDX inline deal cards:** authors type `<DealCard id="…" />`; the map key `DealCard` resolves to `MdxDealCard`, which calls `getDealById` at build time and throws a slug-named `Error` on a miss. Exactly parallel to `<ProductCard slug>` → `MdxProductCard`. Deal cards render through the same `<AffiliateLink>` primitive, so the F0003↔F0007 click contract and `AffiliateClickTracker` are inherited with **no** changes to `lib/analytics.ts`.
>
> **Deal images are staged locally, never hotlinked** — `public/static/images/deals/<post-slug>-<n>.<ext>`, written by `generate:deal-post` through the same `stageImages()` helper the product pipeline uses. `next.config.ts` still has **no** `images.remotePatterns` entry, and adding one is never the fix.

## 6. Risks & edge cases

- **R1 — The stub does not clear the depth floor on its own.** By design (D8), and identical to `scaffold:post`. The risk is a half-finished roundup being committed: `lib/posts.test.ts`'s `TODO`/word-count guards catch it, and US00149 orders prose-writing _before_ `npm run build`. Worth stating in `scripts/README.md` so it never reads like a bug.
- **R2 — Deal images below the 600px cover floor.** Guarded explicitly in §3.6 step 6 rather than left to `assertMinShortSide`. Sampled real images are 1000–1024px.
- **R3 — Duplicate `coverImage` across posts.** `lib/posts.test.ts` asserts no two posts share one. Safe by construction: cover paths are namespaced by post slug, which carries the date — even if the identical Shopee product tops the list two weeks running, the staged paths differ.
- **R4 — Sidecar and post drifting apart.** A hand-deleted sidecar leaves `<DealCard id>` unresolvable; `MdxDealCard` throws at build with the id named, which is the intended loud failure. The reverse (orphan sidecar, deleted post) is harmless — nothing reads it — but is worth a future `sync:content-queue`-style check; not built here.
- **R5 — `discountPercent` inconsistent with the two prices.** Real snapshot data already shows it (`priceVnd === originalPriceVnd` with `discountPercent: 66`). Handled by D5c: the badge shows the tool's number, the strikethrough only renders when it is genuinely meaningful. This repo does not second-guess the tool's figures (spec §5).
- **R6 — Shopee CDN content-type drift.** If the CDN ever serves an unrecognised type, `stageImages` rejects and D5b aborts the run before any write. The failure is loud, local and leaves no partial artefacts.
- **R7 — A second `data-affiliate-link` emitter.** `DealCard` must delegate to `<AffiliateLink>` and never write the attribute itself. The US00144 hardening idea — asserting `grep -rl 'data-affiliate-link' components/ app/` returns only `AffiliateLink.tsx` and the tracker — is worth adding as a test here, since this story is the first to add a new card type since that rule was written.
