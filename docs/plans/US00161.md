# Implementation Plan — US00161: Canonical URLs resolve with 200, not a redirect

**Status:** Done
**Feature:** F0016 — Traffic Foundations
**Spec ref:** `docs/specs/F0016.md` § US00161
**Predecessors:** none (first story of F0016)
**Successors:** US00162–US00167 all emit links/URLs and must follow the no-slash form this story establishes.

---

## 0. The problem in one line

`buildCanonicalPath()` returns `/${joined}/`, every page passes a hardcoded `"/x/"` `path` to `buildPageMetadata()`, and ~25 `<Link href>`/`BASE_PATH` literals end in `/`. Next.js (default `trailingSlash: false`) answers every one of those with `308 → /x`. Google is handed a canonical that redirects.

Fix = flip the composition to no-slash (D1 of F0016), migrate every literal, and add two guards: a Vitest source scan (Scenario 2) and a redirect check in `verify:canonical` (Scenario 3).

## 1. Decisions

- **D1 — `buildCanonicalPath()` returns `/a/b` (root stays `/`).** One-line change in `lib/seo.ts`; every canonical, `og:url`, JSON-LD, breadcrumb `item` and sitemap `<loc>` follows automatically once callers use it.
- **D2 — every `buildPageMetadata({ path })` call site switches from a literal to `buildCanonicalPath([...])`.** Today the post/product/category/policy/listing pages hand-write `path: "/x/"` — that is a second composer, which Scenario 1 forbids ("`buildCanonicalPath()` … remains the only function that composes them").
- **D3 — internal `<Link href>`s stay literal template strings (no-slash), NOT `buildCanonicalPath()`.** `PostCard`, `CatalogGrid`, `PostListingGrid`, `ProductListingClient`, `PostListingClient` are client-bundled; `lib/seo.ts` imports `lib/env.ts`, and a client import of it caused a prod outage (see memory `feedback_env_ts_lazy_eval`). Literal `/bai-viet/${slug}` is safe everywhere, and the Scenario 2 guard is what keeps them honest. Breadcrumb `href`s are built in `lib/breadcrumbs.ts` (server-only, already imports `lib/seo.ts`) so they **do** switch to `buildCanonicalPath()` — they feed `BreadcrumbList` JSON-LD.
- **D4 — no `trailingSlash` config.** Next.js's default `/x/ → 308 /x` is exactly Scenario 4; adding `trailingSlash: true` would invert the problem (spec §5).
- **D5 — the verifier checks every sitemap `<loc>`, not just the 3 samples, with `redirect: "manual"`.** The sitemap is ~45 URLs; HEAD-ing all of them is cheap and catches a regression on any route type (policy pages, About) that the 3-sample approach would miss. Sampled canonicals are checked the same way.

## 3. Design

### 3.1 `lib/seo.ts`

```ts
export function buildCanonicalPath(segments: ReadonlyArray<string>): string {
  const joined = segments
    .map((s) => s.replace(/^\/+|\/+$/g, ""))
    .filter(Boolean)
    .join("/");
  return joined ? `/${joined}` : "/";
}
```

`PageMetadataInput.path` docstring becomes "Root-relative canonical path from `buildCanonicalPath()`, no trailing slash (root is `/`)".

### 3.2 `lib/breadcrumbs.ts`

`PRODUCTS_CRUMB.href = buildCanonicalPath(["san-pham"])`, `POSTS_CRUMB.href = buildCanonicalPath(["bai-viet"])`, category/product/post crumbs likewise. `ROOT_CRUMB` stays `/`.

### 3.3 Pages & components

Mechanical: every `path: "/x/"` → `path: buildCanonicalPath(["x", …])`; every `href="/x/"` / `` `/x/${slug}/` `` / `BASE_PATH = "/x/"` → no trailing slash. Pagination then yields `/bai-viet?page=2` (crawlable, same canonical rule).

### 3.4 Content + supersede

- `content/posts/deal-*-2026-*.mdx` (7 files): `](/bai-viet/<slug>/)` → `](/bai-viet/<slug>)`. (These files are deleted by US00163, but the guard below must pass in this PR.)
- `scripts/deal-roundup/supersede.ts:193` → `[đây](/bai-viet/${currentPostSlug})`; update the matching expectation in `supersede.test.ts`.

### 3.5 Guard — `lib/url-style.test.ts` (new, Scenario 2)

Walks `app/`, `components/`, `lib/`, `scripts/deal-roundup/` (`*.ts`, `*.tsx`, excluding `*.test.*`) and `content/posts/*.mdx`. Flags, with `file:line`:

- TS/TSX: a string/template literal in an href-ish position — `(href|path|BASE_PATH|basePath|destination)\s*[=:]\s*\{?\s*` followed by `"/…/"`, `'/…/'` or `` `/…/` `` where the literal is not exactly `/`.
- MDX: markdown links `](/…/)` and JSX `href="/…/"`.

Asset paths (`/static/…` file references with an extension) and protocol URLs are ignored by construction (they don't end in `/` or aren't root-relative). Failure message: `app/foo.tsx:12 — internal href "/bai-viet/" ends with "/" (canonical form has no trailing slash)`.

The scan is a pure function `findTrailingSlashHrefs(files)` inside the test file, exercised by two fixture cases (one dirty TS line, one dirty MDX link) before the live-repo assertion — so a regex that silently matches nothing can't pass.

### 3.6 `scripts/verify-canonical.ts` (Scenario 3)

- New `checkNoRedirect(artefact, url)` → `fetchImpl(url, { method: "HEAD", redirect: "manual" })`; status 300–399 ⇒ finding `"<url>" answered <status> → <location>`.
- Applied to **every** sitemap `<loc>` (D5) and to each sampled page's canonical URL.
- Report footer unchanged in shape; a clean deployment still prints "All checks passed".

## 5. Execution order

1. Update/add the tests in §4 (red).
2. `lib/seo.ts` (D1) → `lib/breadcrumbs.ts`.
3. App pages (D2), then components/literals (D3).
4. MDX links + `supersede.ts`.
5. `verify-canonical.ts` redirect check.
6. `npm run typecheck && npm run lint && npm run format && npm test && npm run build`.
7. Browser check (`next dev` via `browser_eval`): a post, a product, a category page — view source for canonical/`og:url`/JSON-LD; click a `PostCard`, a breadcrumb, pagination "2" and confirm no 308 hop in the network log.
8. `next start` + the S4 curl.
