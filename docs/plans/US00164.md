# Implementation Plan — US00164: Clean deal display names

**Status:** Done
**Feature:** F0016 — Traffic Foundations
**Spec ref:** `docs/specs/F0016.md` § US00164
**Predecessors:** US00161. Practically after US00163, so the name guard runs over the 3 evergreen sidecars instead of 10 dated ones.
**Successors:** none (independent of US00165–US00167).

---

## 0. Evidence

Real sidecar names today: `"Bàn phím Cơ Razer Không Dây Pro Type Ultra Fullsize *Layout Nhật | HyperSpeed | Switch Yellow | …"`, `"Bàn phím cơ Gaming DAREU EK75 PRO Cloudy Aqua (Đen Xám) - 3 Mode - Hotswap - Bảo hành 24 tháng"`. The product guard (`lib/products.test.ts`, US00131) already bans the worst patterns for fixtures, but deals bypass it entirely.

## 1. Decisions

- **D1 — the rule set lives in `lib/seller-boilerplate.ts`.** `lib/` (not `scripts/`) because `lib/products.test.ts` and `lib/deals.test.ts` are its main consumers and `scripts/` already imports `lib/`. Each rule has an `id`, a human label, and a pattern, so a guard failure can name the broken rule (Scenario 3).
- **D2 — the shared rules are a superset of today's product guard:** `!`, `|`, `[…]`, `【…】`, "chính hãng", "giá rẻ", `BH n tháng`, **`Bảo hành n tháng`** (the long form appears in real data), "freeship", "cam kết" — all case-insensitive. Two changes for products: `CAM KẾT` becomes case-insensitive and brackets are newly banned. Checked 2026-10-18: no current product name trips either, so the product guard stays green.
- **D3 — cleaning happens in `loadRankedDeals()` (`scripts/deal-roundup/source.ts`).** That's where per-deal drops are already reported through `DroppedDeal`, so Scenario 4's "dropped and reported" needs no new reporting path. `RankedDeal.name` becomes the cleaned name; a new `RankedDeal.rawName` keeps the seller title for the run summary. The generator already writes `d.name` to both the sidecar and the `h3`.
- **D4 — `cleanDealName()` strips seller boilerplate only; it doesn't try to "editorialise".** It keeps a leading "Chuột Gaming …" category prefix. Rewriting that is the operator's job (Scenario 5) or a later rule.
- **D5 — the guard also checks that the `h3` and the sidecar `name` match.** Scenario 5 lets the operator hand-edit names. A test that each `<DealCard id>` is preceded by `### <n>. <deal.name>` turns "keep them in sync" from an instruction into an enforced rule.
- **D6 — the 3 existing evergreen sidecars and their `h3`s are cleaned in this PR**, by running `cleanDealName()` over them (throwaway `tsx -e`, not committed) and then reviewing the result by hand. Without that, the new guard fails on day one.

## 3. Design

### 3.1 `lib/seller-boilerplate.ts`

```ts
export interface BoilerplateRule {
  id: string;
  label: string;
  pattern: RegExp;
}

export const SELLER_BOILERPLATE_RULES: readonly BoilerplateRule[] = [
  { id: "pipe", label: '"|" segment separator', pattern: /\|/ },
  { id: "bracket", label: "[…] / 【…】 promo segment", pattern: /[[\]【】]/ },
  { id: "bang", label: '"!"', pattern: /!/ },
  { id: "chinh-hang", label: '"chính hãng"', pattern: /chính hãng/i },
  { id: "gia-re", label: '"giá rẻ"', pattern: /giá rẻ/i },
  { id: "warranty", label: '"BH/Bảo hành n tháng"', pattern: /\b(BH|Bảo hành)\s*\d+\s*tháng/i },
  { id: "freeship", label: '"Freeship"', pattern: /freeship/i },
  { id: "cam-ket", label: '"cam kết"', pattern: /cam kết/i },
];
export const MAX_DISPLAY_NAME_LENGTH = 70;
export const MIN_DISPLAY_NAME_LENGTH = 3;

/** Every rule a display name breaks, incl. length; [] = clean. */
export function findBoilerplateViolations(name: string): BoilerplateRule[];
```

### 3.2 `cleanDealName(raw: string): string | null`

1. Remove `[…]` and `【…】` segments (incl. contents).
2. Keep only the text before the first `|`.
3. Remove `!`, then every phrase rule (`chính hãng`, `giá rẻ`, warranty, `freeship`, `cam kết`), case-insensitive.
4. Remove now-dangling separators (`-`, `–`, `,`, `+`, `/` at either end, or repeated), and collapse whitespace.
5. If longer than 70: cut at the last space ≤ 70 and trim trailing separators.
6. Under 3 chars → `null`.
7. Post-condition: `findBoilerplateViolations(result)` is `[]`. Asserted in tests so the cleaner and the guard can't drift.

### 3.3 `loadRankedDeals()`

After the affiliate-URL check: `const name = cleanDealName(raw.name); if (!name) dropped.push({ rank, name: raw.name, reason: "name empty after removing seller boilerplate" })`. F0015 order and slicing semantics are unchanged.

### 3.4 Guards in `lib/deals.test.ts`

- For each deal in `getAllDeals()`, `findBoilerplateViolations(deal.name)` must be empty. Failure message: `deal "deal-chuot-gaming-2": name "…" breaks rule "pipe" ('"|" segment separator')`.
- For each roundup post, each `<DealCard id="X" />` is preceded by `### <n>. <name of X>`. Failure names the post slug and deal id.

## 5. `/deal-roundup` doc changes

- Step 5 gains: "You may shorten or refine a deal name (for example drop the category prefix). If you do, edit the sidecar `name` **and** the matching `### n.` heading together. `npm test` checks both the boilerplate rules and that they match."
- The rule "Never hand-edit `content/deals/*.json`" is narrowed to: "only the `name` field may be hand-edited, per step 5".

## 6. Execution order

1. `seller-boilerplate.ts` + tests → refactor `lib/products.test.ts` (must stay green).
2. `clean-name.ts` + tests → wire into `source.ts` / `deal.ts` / `report.ts` (print `rawName → name` in the summary).
3. `deals.test.ts` guards (red on current sidecars).
4. D6: clean the 3 sidecars + `h3`s, then review them by hand (green).
5. Doc updates. Then `typecheck`, `lint`, `format`, `test`, `build`, and a browser check of the three deal pages (headings read cleanly, cards unchanged).
