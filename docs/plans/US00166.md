# Implementation Plan — US00166: A real author and a visible methodology

**Status:** Approved
**Feature:** F0016 — Traffic Foundations
**Spec ref:** `docs/specs/F0016.md` § US00166
**Predecessors:** US00161 (no-slash URLs), US00162 (`isRoundupPost()` in its reduced form).
**Successors:** none.

> **Blocked on the site owner for merge, not for implementation (D4 of F0016).** Real name, URL slug, Vietnamese bio (2–4 short paragraphs), optional photo and optional profile links are needed. Until they arrive, the registry holds a placeholder and `npm test` fails on purpose (Scenario 6), so the PR can't go green.

---

## 1. Decisions

- **D1 — `lib/authors.ts` is the author registry**, built the same way as `lib/categories.ts`: a typed map plus `getAuthor()` / `getAllAuthors()` / `assertAuthorRegistered()`, and `PRIMARY_AUTHOR_SLUG` for posts with no `author` in their frontmatter.
- **D2 — the placeholder is explicit:** an `AUTHOR_PLACEHOLDER = "TODO(author)"` sentinel. `lib/authors.test.ts` fails on any field that contains it, naming the author slug and the field.
- **D3 — route `/tac-gia/[slug]`**, a Vietnamese slug like every other route, statically generated per registered author. The methodology section has the anchor `#cach-chon-san-pham`.
- **D4 — breadcrumb trail is `Trang chủ › Bài viết › <Author name>`.** There's no `/tac-gia` index page, and every crumb in the trail has to be a real link. `buildAuthorBreadcrumbs(author)` goes into `lib/breadcrumbs.ts`.
- **D5 — the methodology note sits at the end of the article, before related posts.** A deal post already has two notices at the top (affiliate disclosure and price disclaimer), and a third would push the content below the fold. The two versions of the copy are constants in `lib/disclosures.ts`: `METHODOLOGY_GUIDE_VI` and `METHODOLOGY_DEAL_VI`. Picking between them uses `isRoundupPost()`.
- **D6 — the Article JSON-LD author is resolved inside `buildArticleSchema()`**, via `getPostAuthor(post)`. Call sites don't change. `publisher` stays the `MuaGear` Organization (Scenario 3).
- **D7 — the About page's existing "how we pick" section stays.** The author page has the canonical methodology text; the About page gets a one-line link to it. The About page copy isn't otherwise rewritten.

## 3. Design

### 3.1 `lib/authors.ts`

```ts
export interface Author {
  slug: string; // kebab-case ASCII
  name: string;
  jobTitle?: string; // e.g. "Biên tập viên"
  bio: string[]; // Vietnamese paragraphs
  avatar?: string; // root-relative /static/images/authors/…
  sameAs?: string[]; // optional external profiles
}
export const PRIMARY_AUTHOR_SLUG: string;
export function getAllAuthors(): Author[];
export function getAuthor(slug: string): Author | undefined;
export function assertAuthorRegistered(slug: string, postSlug: string): void; // throws "post "<x>": unknown author "<y>""
export function getPostAuthor(post: Post): Author; // frontmatter author ?? PRIMARY
export function authorPath(slug: string): string; // "/tac-gia/<slug>" — literal, client-safe (US00161 D3)
```

`lib/posts.ts` validates `author` when it's present: it must be a string and a registered author. Otherwise `next build` fails naming the post slug and the unknown author (Scenario 1).

### 3.2 Author page

`generateStaticParams` comes from `getAllAuthors()`. Metadata comes from `buildPageMetadata({ title: author.name, description: <first bio paragraph>, path: buildCanonicalPath(["tac-gia", slug]), ogImage: author.avatar })`.

The page itself, in order:

- `<Breadcrumb>` plus its BreadcrumbList `<JsonLd>`.
- An `<h1>` with the name. The avatar uses `next/image` when there is one.
- The bio paragraphs.
- `<section id="cach-chon-san-pham">` with `<h2>Cách chúng tôi chọn sản phẩm</h2>`. It covers two things: how buying guides are researched, and how deal roundups are chosen (Shopee's discount, rating and sales ranking, not tested hands-on).
- `<h2>Bài viết của {name}</h2>` and a `PostCard` grid of that author's posts, newest first.
- `<JsonLd data={buildPersonSchema(author)} />`.

### 3.3 `lib/person-schema.ts`

`{ "@context", "@type": "Person", name, url: absoluteUrl(buildCanonicalPath(["tac-gia", slug])), description: bio[0], jobTitle?, image?: absoluteUrl(avatar), sameAs?, worksFor: { "@type": "Organization", name: SITE_NAME, url: getSiteUrl() } }`.

### 3.4 Post page

- Byline: `<span className={styles.byline}>Bởi <Link href={authorPath(a.slug)}>{a.name}</Link></span>`, replacing the bare `SITE_NAME`.
- `<MethodologyNote variant={isRoundupPost(post) ? "deal" : "guide"} authorSlug={a.slug} />` after `<PostBody>`. It renders a short `<aside>` with the copy and a link to `/tac-gia/<slug>#cach-chon-san-pham`.

### 3.5 Article schema

`author: { "@type": "Person", name, url: absoluteUrl(buildCanonicalPath(["tac-gia", slug])) }`. `publisher` keeps the Organization object.

### 3.6 Sitemap

One entry per author: `{ url: absoluteUrl(buildCanonicalPath(["tac-gia", slug])), lastModified: <newest updatedAt ?? publishedAt among their posts> }`.

## 5. Execution order

1. Ask the owner for the author details. Start with `TODO(author)` placeholders if they aren't in yet.
2. Write the tests (red).
3. `lib/authors.ts` → `types/post.ts` / `lib/posts.ts` → `person-schema.ts` → `article-schema.ts` → `breadcrumbs.ts` → `disclosures.ts`.
4. Author route → `MethodologyNote` → post page → sitemap → About page link.
5. Fill in the real details and add the avatar to `public/static/images/authors/` if one is supplied. Run `typecheck`, `lint`, `format`, `test` and `build`.
6. Browser check: a guide, a deal page and the author page, at desktop and mobile widths. Validate the author page's JSON-LD in Google's Rich Results Test after deploy (operator step).

## 6. Structure-doc impact

- Route map: `/tac-gia/[slug]` → `app/tac-gia/[slug]/page.tsx`. Add it to the "Routes" block too.
- Tree: `lib/authors.ts`, `lib/person-schema.ts`, `components/MethodologyNote.tsx`, `public/static/images/authors/`.
- New convention: **authors live in one place, `lib/authors.ts`**. An unknown frontmatter `author` fails the build, and a placeholder fails `npm test`.
- Update the JSON-LD convention: Article `author` is a Person, `publisher` is the Organization. Person JSON-LD is built by `lib/person-schema.ts`.
- Add `author?` (optional) to the MDX frontmatter block.
- Disclosures section: the methodology note shows on every post, with deal and guide variants.
