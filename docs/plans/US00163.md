## 1. Decisions

- **D1 — the migration is a one-time, reviewed content change, not a committed script.** The steps are mechanical (`git mv`, id rewrite, frontmatter edit, delete) and run once; a permanent `scripts/migrate-*.ts` would be dead code the day after. What _is_ durable — the redirect list and the guards — lives in `lib/`.
- **D2 — the redirect list is explicit data in `lib/redirects.ts`, imported by `next.config.ts` with a relative path.** Ten literal `{ source, destination, permanent: true }` entries, no pattern: a regex like `/bai-viet/deal-:cat-:date(\\d{4}-…)` would also catch slugs that never existed. The module has **no `@/` imports** (path aliases are not guaranteed to resolve while Next loads `next.config.ts`); the test cross-checks it against `roundupSlugFor()`.
- **D3 — images are left exactly where they are.** Seeds already reference `deal-<category>-2026-10-12-<n>.<ext>`, which matches US00162's dated naming, so nothing is renamed. Deletion runs through US00162's `findUnreferencedDealImages()`, "unreferenced" rather than a filename pattern (spec §5).
- **D4 — trailing-slash variants take two hops** (`/x/ → 308 /x → 308 /bai-viet/deal-<cat>`): Next's built-in trailing-slash redirect runs before `redirects()`. Both hops are permanent and Google follows chains; Scenario 1 holds ("answers a permanent redirect" and lands on the evergreen URL). Not worked around: a custom `/x/` source would never be reached.

## 3. Migration steps (per category, then once)

For each of the three categories:

1. `git mv content/posts/deal-<cat>-2026-10-12.mdx content/posts/deal-<cat>.mdx` and the same for `content/deals/…json`.
2. Rewrite ids `deal-<cat>-2026-10-12-<n>` → `deal-<cat>-<n>` in the sidecar **and** in the post's `<DealCard id="…">` embeds (5 each; `sed` scoped to those two files, then a diff review).
3. Frontmatter: `publishedAt` → earliest date from §0; add `updatedAt: "2026-10-12"`. Keep `title`/`summary` (already "tuần này" framing).
4. Remove the `{/* roundup-lead:start */}` / `{/* roundup-lead:end */}` marker lines (keep the paragraph between them).

Then:

5. `git rm` the 7 remaining dated `.mdx` + 7 sidecars.
6. Run `findUnreferencedDealImages()` via a throwaway `tsx -e` from the scratchpad (not committed), print the list, `git rm` each file. Paste that list into the PR body.
7. Add `lib/redirects.ts` + `next.config.ts` `redirects()`.

## 4. Design

### 4.1 `lib/redirects.ts`

```ts
export interface LegacyRedirect {
  source: string;
  destination: string;
  permanent: true;
}

export const LEGACY_ROUNDUP_REDIRECTS: readonly LegacyRedirect[] = [
  {
    source: "/bai-viet/deal-chuot-gaming-2026-09-27",
    destination: "/bai-viet/deal-chuot-gaming",
    permanent: true,
  },
  // … 9 more, one per dated slug in §0
];
```

```ts
// next.config.ts
import { LEGACY_ROUNDUP_REDIRECTS } from "./lib/redirects";
const nextConfig: NextConfig = {
  pageExtensions: [...],
  async redirects() { return [...LEGACY_ROUNDUP_REDIRECTS]; },
};
```

### 4.2 Guards — `lib/redirects.test.ts` (Scenario 4) and `lib/roundups.test.ts` (Scenario 3)

- No redirect `source` slug equals an existing `getAllPosts()` slug → fail naming the colliding slug.
- Every `destination` slug exists as a post, and equals `roundupSlugFor(<category of that post>)`.
- No `source`/`destination` ends with `/`; every entry `permanent: true`; no duplicate sources.
- Live content: `assertOneRoundupPerCategory(getAllPosts())` passes, i.e. every post with a sidecar has slug `deal-<its category>` — no dated roundup can come back unnoticed.

## 7. Structure-doc impact

- Tree: `lib/redirects.ts` + `lib/redirects.test.ts`; `next.config.ts` row mentions `redirects()` sourced from it.
- New convention bullet: **permanent redirects are config-level data in `lib/redirects.ts`** — never middleware or a route handler (SSG-only); a source may never shadow a live post (test-enforced); `lib/redirects.ts` must stay alias-free because `next.config.ts` imports it.
- `content/deals/` / `content/posts/` rows: exactly one `deal-<category>` roundup per category.
