# Implementation Plan — US00165: Skip recently featured products

**Status:** Done
**Feature:** F0016 — Traffic Foundations
**Spec ref:** `docs/specs/F0016.md` § US00165
**Predecessors:** US00162 (fixed-slug generator), US00163 (seeded sidecars, which get backfilled with ids here).
**Successors:** none.

---

## 0. A blocker the spec doesn't mention

The scrape tool's snapshot only holds **`top_n` deals per keyword**. Every committed snapshot has exactly 5/5/5, even with `totalFound` 60–120. `/deal-roundup` calls the tool with `top_n = --top`, so after skipping recent picks there's nothing left to backfill from, and the feature would just shrink the roundup.

**Fix (D1):** `/deal-roundup` calls the scrape tool with `top_n = top × (repeatWindow + 1)`, which is 20 with the defaults. The tool still ranks the deals and its order is still the order we use. We only read further down its list.

## 1. Decisions

- **D1:** request a deeper scrape, as above. In this repo it's a change to `.claude/commands/deal-roundup.md` only, no code.
- **D2 — history file: `data/deal-history/<category>.json`, committed.** It sits next to `data/deals/` (the audit trail of what the tool returned) and records what we actually featured.
  ```json
  {
    "category": "chuot-gaming",
    "runs": [{ "date": "2026-10-12", "items": [{ "itemId": 41773751059, "shopId": 1641177081 }] }]
  }
  ```
  Runs are kept sorted by date ascending, and the file is written pretty-printed.
- **D3 — recency means "the last `window` runs dated before today"** (counted in runs, not weeks). Today's own entry never counts against itself (Scenario 4). Recording a run replaces any entry for the same date.
- **D4 — only recency skips are backfilled.** The algorithm walks the tool's list in order. A deal that is recent, or that has no `itemId`/`shopId`, is skipped and doesn't use up a slot. The next `top` deals that remain then go through F0015's checks (affiliate URL) and US00164's name cleaning, and those drops are **not** backfilled. That keeps F0015's shortfall behaviour as it is. The ordering rule ("never re-sorts or re-scores") still holds: skipping only ever removes items from the list.
- **D5 — a deal with no `itemId`/`shopId` is dropped and reported** (spec §5). We can't track it for recency, so it never gets featured. The check lives in `source.ts`, not in the shared `parseDealsSnapshot()`, which would make the F0012 ingest path fatal as well.
- **D6 — sidecar `Deal` gains `itemId` and `shopId`.** They're optional in the type and loader (numbers when present) so the US00163 seeds still load. New writes always include them. The seeds and the history are backfilled once (D7).
- **D7 — one-time backfill in this PR.** For the 3 seed sidecars, `itemId`/`shopId` come from `data/deals/2026-10-12.json`, matched on `affiliateUrl` (checked 2026-10-18: 5/5 match for chuot-gaming). Each category's history is seeded with its 3 most recent dated runs from the committed snapshots and the deleted sidecars in git history (09-27…10-12). That way the very next run already skips repeats. The backfill uses a throwaway `tsx -e` script in the scratchpad, and the result goes in the PR.

## 3. Design

### 3.1 `scripts/deal-roundup/history.ts`

```ts
export interface DealHistory {
  category: string;
  runs: { date: string; items: DealKey[] }[];
}
export interface DealKey {
  itemId: number;
  shopId: number;
}

export function dealKey(k: DealKey): string; // `${shopId}:${itemId}`
export function readHistory(category: string, dir?: string): DealHistory; // missing ⇒ empty; malformed ⇒ throw naming path
export function recentKeys(h: DealHistory, window: number, today: string): Set<string>; // last `window` runs with date < today
export function recordRun(h: DealHistory, date: string, items: DealKey[]): DealHistory; // replace same-date, keep sorted; pure
export function writeHistory(h: DealHistory, dir?: string): string;
```

"Malformed" covers: invalid JSON; a `category` that doesn't match the file name; a run with a malformed date; an item whose ids aren't numbers.

### 3.2 `loadRankedDeals(args, { dealsDir, recent })`

```ts
const eligible: RawDeal[] = [];
for (const raw of rawDeals) {                        // tool order
  if (eligible.length === args.top) break;
  if (!Number.isFinite(raw.itemId) || !Number.isFinite(raw.shopId)) { dropped.push(…"no itemId/shopId"); continue; }
  if (recent.has(dealKey(raw))) { skippedRecent.push(…); continue; }
  eligible.push(raw);
}
// then the existing per-deal affiliate + name checks over `eligible`
```

The result gains `skippedRecent: { rank, name }[]`. `RankedDeal` gains `itemId` and `shopId`.

### 3.3 Generator

Before loading: `history = readHistory(category)` and `recent = recentKeys(history, args.repeatWindow, date)`. After the post and sidecar are written: `writeHistory(recordRun(history, date, deals.map(({itemId, shopId}) => ({itemId, shopId}))))`. Nothing is written on `--dry-run` or when there are zero deals, so the history doesn't change on a quiet week.

### 3.4 Args & report

`--repeat-window=<n>`: an integer ≥ 0, default 3. A negative number, a non-integer or an empty value is a parse error naming the flag (Scenario 5). The footer becomes `… requested 5, usable 4 · skipped as recent: 3`, with each skipped deal listed under a `Skipped as recent (K):` group.
